# 围棋在线 (Weiqi Online)

一个极简轻量、即开即下、随时随地与好友联机下围棋的 Web 应用程序。支持手机与电脑跨端自适应对弈。

---

## ✨ 核心特性

### 1. ⚔️ 正规对战模式（还原图一）
- **棋盘规格**：9×9 路、13×13 路、19×19 路自由切换。
- **开局设置**：
  - 执黑 / 随机 / 执白座位分配。
  - 让子设置：0 至 9 子（自动落于标准星位）。
  - 贴目设置：默认 6.5 目，支持自由微调。
  - 时间控制：无时间限制、1分+10秒、1分+20秒、15分+20秒、自定义加秒制。
- **好友联机**：一键复制邀请链接，好友在手机浏览器或电脑浏览器打开链接即可直接入座对弈。
- **正规围棋规则引擎**：
  - 严格连通块（Group）气数（Liberties）计算与实时吃子提子。
  - 自杀禁着点判定（无气不可下子，但能提吃对方时除外）。
  - 打劫规则（单劫禁全同，禁止立即回提）。
- **终局点目判断胜负**：
  - 双方连续停着或主动点目进入终局阶段。
  - 自动泛洪搜索黑白领地（数目法与数子法双重支持）。
  - 支持在棋盘上直接点击标记死子（死子自动显带 ✕ 且地域划归对方），实时重新计算并裁定胜负。

### 2. 🎓 教学摆棋模式（还原图二蓝色虚线框）
- **摆棋模式切换**：
  - `● 只下黑子`：方便连续摆放黑子阵型或黑先做活题。
  - `○ 只下白子`：方便连续摆放白子死活题或白棋杀气。
  - `◑ 正常交替`：恢复黑白轮流落子。
- **实时控制按钮组**：
  - `[ 停着 ]`：放弃本手。
  - `[ 撤销 ]`：悔棋，退回上一手。
  - `[ 重做 ]`：前进恢复被撤销的一手。
  - `[ 重新开始 ]`：清空盘面，重置为新局。
- **历史步数回溯与分支尝试**：
  - 步数导航（`|<`, `<`, `第 N 手`, `>`, `>|`），师生可随时跳回到任意手，尝试不同的下法变化。
- **双端毫秒级实时同步**：
  - 老师或学生在任意端摆棋、切换颜色、悔棋，另一端立刻无感同步更新。
- **辅助功能**：
  - `[ 🔢 显示手数 ]`：在棋子上显示 1, 2, 3... 步数编号。
  - `[ 📊 试算点目 ]`：教学中随时评估当前盘面目数优劣。

### 3. 🎨 高质感视听体验
- **高逼真木质棋盘**：天然暖木纹理底色，标准星位与清晰坐标（A-T排除I字母，1-19数字）。
- **3D 光影棋子**：拟真黑曜石微光与温润白玉质感，伴随落子下沉立体投影。
- **真实敲子音效**：采用 Web Audio API 合成真实实木棋盘敲击回响与提子音效，零依赖零卡顿。

## 🚀 启动与使用指南

### 1. 启动服务
确保已安装 Node.js（Node 20.18+；本次验证使用 Node 24.15.0），在项目目录下执行：

```bash
# 安装锁定版本的依赖并测试
npm ci
npm test
# 启动本地服务器
npm start
```
服务默认运行在：`http://localhost:3000`

### 2. 与好友联机对弈
1. 在浏览器打开 `http://localhost:3000`。
2. 点击弹窗或顶部右上角的 **“🔗 邀请好友”** 按钮，链接自动复制到剪贴板。
3. 将链接发送给朋友（例如微信、QQ 或浏览器直接打开）。
4. 朋友进入链接后将自动入座为白方（或对局另一方），即可立刻开始下棋！

### 3. 局域网/手机对战
如果朋友在同一 Wi-Fi 或局域网内，可将链接中的 `localhost` 替换为本机内网 IP（例如 `http://192.168.1.100:3000/?room=ABC123`），朋友即可在手机浏览器上随时随地落子！


## 1.1.0 修复说明

- 棋盘切换由服务器执行并广播，不再用新建房间模拟修改尺寸。教学中切换会清空摆棋；对战已经落子时须先双方同意新一局。
- 点目支持取消并继续对局，死子和确认状态实时同步；关闭结果面板后不会被后续同步强制弹回。双方都确认后才结束对战。
- 新增独立“形势估算”，只返回当前盘面快照，不暂停对局或计时。采用有限距离影响范围的粗估，不是 AI 死活判断，不能用于正式裁决。
- 同一房间重复加入不改变座位。换房先退出旧房间；无人旧房立即清理；普通断线空房保留 60 秒，未加入的预建房也在 60 秒后清理。仍有其他参与者的房间保留。
- 断线缺少对手时暂停对战计时，重新加入后恢复。观战者不能落子、点目确认、重置或改棋盘。
- 修复零贴目、和棋、停着扣时与加秒、撤销/重做及历史跳转顺序、路径邀请链接的资源加载、事件通知和断线操作提示。
- 限制消息大小、房间总数和创建频率，升级存在已知漏洞的依赖。

### 验证

`npm test` 包含原有规则测试、房间生命周期与状态机回归测试、自动启动独立服务的真实 HTTP/WebSocket 多客户端测试。

### 部署现有 Render 服务

本地修改不会自动改变线上服务。将经过测试的提交合并并推送到 Render 关联的 GitHub 分支（通常是 main）。若配置为 On Commit，Render 会自动构建并启动新版本；若关闭自动部署，使用 Manual Deploy → Deploy latest commit。只选 Restart service 会继续运行已部署的旧提交。

建议构建命令 `npm ci && npm test`，启动命令 `npm start`。部署成功后访问 `/health`，应返回版本 `1.1.0`，并刷新客户端页面以加载新前端。

官方说明：https://render.com/docs/deploys

当前房间存储在单个服务进程内存中：发布、服务器重启或平台休眠会清空房间。请在无人进行对局时发布。此版本没有数据库持久化、账号绑定座位或多实例房间同步；分享房间链接应只发给可信的参与者。点目为简化地域/面积计数，双活、复杂劫争和完整赛事规则需另行处理。


### 全站服务器状态（1.2.0）
房间页面显示 CPU、RSS 内存、有人房间/总房间、待清理空房间和在线 WebSocket 连接数。服务器每 5 秒采样并通过现有连接广播；断线或超过 12 秒未收到更新时显示待更新，避免旧数值误导。窄屏时面板移到棋盘上方。
CPU 以单核 100% 为基准（多核可超过 100%），不是 Render 套餐配额百分比；内存为当前围棋进程 RSS，不是宿主机或其他服务的内存。当前单进程部署下覆盖全站，若未来部署多实例需要聚合统计。公开 `/api/server-stats` 只返回聚合指标，不包含房间 ID、玩家信息或凭据。


### 棋盘形势标记（1.3.0）
形势估算改为非模态面板和黑白方块，宽屏左侧、窄屏棋盘上方，不阻挡落子。使用 MIT 许可 OGS score-estimator（源码版本、编译命令见 public/vendor/ogs/README.md），在浏览器 Web Worker 中运行 1000 次随机模拟；新盘面取消旧任务，15 秒超时后可手动重试，关闭/换房/断线/进入正式点目时清除覆盖层。运行时只加载本站 JS/WASM，无外部 API、模型下载或服务器分析开销。预计面积与贴目统一显示，疑似死子不自动改动棋局。它比旧版距离粗估包含更多模拟及棋形处理，但不是 KataGo 神经网络，也不能保证复杂死活/双活/劫争正确。旧 request_estimate 协议暂留作旧客户端兼容，新界面不使用它。
